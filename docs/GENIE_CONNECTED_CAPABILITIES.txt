Source connectivity evidence: declaration names are checked against the Live
dispatch set; all bridge functions call the existing ComputerService rather than
creating a second executor. ComputerService enforces PTE scope, safe mode and
high-risk confirmation; UIA elements expire and are revalidated before action.
The model receives the current bridge catalog, and tool/page text is fenced as
untrusted evidence. Direct actions do not require a durable Mission; larger
multi-step work follows the orchestrator/Mission path.

Permission/dependency notes:
  - Owner grant, safe-mode policy, exact UIA element and Windows integrity level
    determine availability. A code path is not authorization.
  - Browser CDP tools address only the authorized GENIE/CDP session. A named or
    default URL handoff does not guarantee access to an existing signed-in tab.
  - Search requires a configured provider for typed model planning and an
    available browser/search endpoint; site gates/CAPTCHA stop the action.
  - Gemini Live requires a valid Gemini credential, network, audio devices and
    owner-started Live session. No microphone was opened in this audit.

2. CONVERSATION, HISTORY AND MISSION CONTRACTS
==============================================
Conversation archive:
  core/session_store.py persists bounded owner-session turns in the database;
  core/lifecycle.py writes typed turns and voice/live.py records Live turns into
  the same owner conversation store. History API supports pagination and clear.
  Verification exercised archive pagination, session isolation and persistence
  across database reopen in tests/unit/test_connectivity_closure.py.

Mission lifecycle:
  missions/service.py owns durable records; missions/runner.py executes a
  bounded plan through the shared worker; missions/scheduler.py handles due
  schedules; missions/control.py resolves pause/resume/cancel; IPC exposes list,
  plan, progress, run, pause, resume, cancel and delete. Deletion rejects active
  work and accepts settled work. The WPF Missions delete action is enabled only
  for history/settled rows. Unit coverage verified settled-only deletion and
  that routine direct app actions do not create durable Missions.
